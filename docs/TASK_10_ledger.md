# TASK_10 记账（零花钱）

> 本文件是记账功能的唯一规则依据。凡是零花钱入账、零钱 / 存款、利息、对账、记账权限相关的改动，
> 先读本文件；实现与本文件不一致时，以本文件为准。需要偏离本文件时，先向用户说明并取得确认，
> 再同步修改本文件。零花钱怎么挣（1 分 = 1 元、每周结算）见 `docs/TASK_09_points.md` §5。
>
> 规则确定日期：2026-11-24

## 1. 目的

- 积分换成零花钱以后，孩子要知道自己有多少钱、花在哪里、存了多少。
- 孩子在 iPad 上自己记账，家长在 Mac 上也能看和管理；钱实际在孩子的微信里，账本要能和微信对上。
- 用利息鼓励存钱：只有存满一个月的钱才有利息。

## 2. 账户

| 账户 | 含义 | 对应微信 |
|---|---|---|
| 零钱 | 可以自由花的钱 | 钱包零钱 |
| 存款 | 存起来的钱 | 零钱通 |

**余额不单独保存**，由记录算出（删掉的记录不算）。存多少由孩子自己决定，不设比例。

## 3. 记录类型

| 类型 | 账户变化 | 谁能记 |
|---|---|---|
| 练习奖励 | 零钱 +N | 每周日晚 8 点结算后自动生成"待转账"；家长在 Mac 上点"已转账"才入账 |
| 支出 | 零钱 −N | 孩子和家长 |
| 存进存款 | 零钱 −N，存款 +N | 孩子和家长 |
| 从存款取出 | 存款 −N，零钱 +N | 孩子和家长 |
| 利息 | 存款 +N | 每月 1 日自动生成"待转账"；家长在 Mac 上点"已转账"才入账 |
| 期初余额 | 设定零钱和存款的起始金额 | 只有家长 |
| 对账调整 | 零钱或存款 ±N，必须写原因 | 只有家长 |

每条记录包含：日期、类型、金额（元，保留两位小数；内部按"分"存整数）、内容（支出必填，例如"买文具"；
对账调整写原因；利息写算法）、分类（支出必选：吃的、文具、书、玩具、礼物、其他）。

- 期初余额：零钱、存款各一条；再设一次就是改那一条，设成 0 就删掉。
- 练习奖励、利息的记录 id 固定（`allowance-那周周一`、`interest-月份`），两台设备同时点"已转账"也只有一条；
  入账记录被删掉（软删）后，那一项会重新出现在待转账里。
- **本月收入** = 练习奖励 + 利息；**本月支出** = 支出。存进 / 取出只是在零钱和存款之间挪，期初余额和对账调整都不算收支。

## 4. 规则与权限

家长判断沿用 `docs/TASK_09_points.md` §7：**非触摸设备（Mac）= 家长**（`navigator.maxTouchPoints > 0` 视为触摸设备）。

1. **余额不够时（孩子）**（2026-11-25 用户改）：
   - **支出：零钱不够也让记，零钱记成负数**（例如零钱 3 元、买了 5 元的东西，零钱 −2 元）；记的时候弹窗里提示"零钱只有 x 元，记下后零钱是 −y 元；以后挣的零花钱会先把它补上"。之后练习奖励入账（零钱 +N）自然把负数补上，不另外记"还钱"。
   - 存进存款：零钱不够不让存，提示"零钱不够，找妈妈对账"（没有的钱挪不进存款）；
   - 从存款取出：存款不够不让取，提示"存款不够，找妈妈对账"（存款不会是负数，利息按最低日终余额算也不受影响）。
   家长不受这些限制（例如补记以前忘记的支出），记错了用对账调整修正。
2. **孩子只能记今天的**（不能选日期），只能记支出、存进存款、从存款取出。
3. **孩子只能修改、删除当天自己记的记录**（记录日期是今天、今天创建、孩子记的）；更早的记录、家长记的、
   练习奖励 / 利息 / 期初余额 / 对账调整，孩子都改不了，只有家长在 Mac 上能改。
4. **删除一律软删除**（记下删除时间，记录还在，余额不再算它）。删除要再点一次"确定删掉"。
5. 存多少由孩子自己决定，不设比例。

## 5. 练习奖励（待转账）

- 每周日晚上 8 点起结算这一周（`docs/TASK_09_points.md` §5），结算快照里固定那周的零花钱
  = 练习分 + 家长奖励和扣分，不低于 0。
- 记账页的"待转账"列出已结算、还没入账的周："11/23–11/29 练习奖励 N 元"。**金额取自结算快照**，
  快照之后的补勾、撤回奖励都不影响已经结算（发放）的金额。0 元的周不列。
- 家长在 Mac 上把钱转到孩子微信零钱后点"已转账"，生成一条练习奖励记录（记在点的那天），零钱 +N。
- 孩子在 iPad 上看到的是"等转账"，没有按钮。

## 6. 利息

- **月利率默认 5%**，家长可在 Mac 上修改（记账页右上角"月利率"），保存在设置里（app_settings `ledger_settings_v1`）。
- **算法**：每月 1 日计算上个月的利息 = 上个月存款的**最低日终余额** × 月利率，**保留到角（四舍五入）**。
  - 日终余额 = 那一天结束时的存款余额（当天先取后存，只看结束时）。
  - 取一个月里每天日终余额的最小值，所以**月中、月底才存进去的钱不计利息，只有存满一个月的钱才有利息**；
    月中取出又存回，取出那几天的低点就是最低日终余额。
  - 例：12 月一直有 100 元 → 1 月 1 日生成"12 月利息 5 元"；12 月 31 日才存进 150 元 → 12 月没有利息，1 月存满了，2 月 1 日有。
- **第一次计息从 2026 年 12 月开始**：2027 年 1 月 1 日生成 12 月的利息；11 月不计息。之后每月 1 日生成上个月的。
- 利息为 0 的月份不列待转账。
- 利息以"待转账"出现，家长在 Mac 上转进孩子的零钱通后点"已转账"入账（存款 +N），记录旁写明算法，
  例如"12月最低存款 100 元 × 5% = 5 元"。入账的利息算进之后月份的存款。
- **利率修改只影响之后计算的月份**：改利率从"改的那个月"起生效（11 月里改的从 12 月起）。
  这个月的利息下月 1 日才算，所以会用新利率；已经过去的月份（1 日已经算出来了，不管转没转账）不受影响。
  例：1 月 3 日改成 10%，12 月的利息仍按 5%，1 月起按 10%。同一个月改两次，以后改的为准。
- 记账页存款余额下方显示"这个月不取钱的话，下月 1 日能拿到 X 元利息"，
  X = 本月到今天为止的最低日终余额 × 本月月利率（保留到角）。12 月之前（还没开始计息）只显示"每月 1 日结算上个月的利息"。

## 7. 页面

入口：左侧菜单（窄屏为底部标签栏）"记账"（2026-11-25 起一级菜单为今日 / 计划 / 课表 / 统计 / 记账 5 项）；首页积分条上点"零钱 / 存款"也能进。

版式参照常见记账软件（2026-11-24 用户要求“更专业”）。iPad 上整页一屏放下（2026-11-25）：左栏是下面 1–4、6、7，右栏只放流水（5），各自在栏里滚动；电脑、手机照常一列 / 两栏往下排。

1. 顶部总资产卡：总资产（零钱 + 存款），下面分两格零钱、存款，最下面一行利息提示（本月利息预估，或"每月 1 日结算上个月的利息"）。
2. 本月收入 / 本月支出 / 本月结余三格。
3. 快捷记账：**"记一笔支出"是醒目的实心大按钮**（记账先按它，2026-11-25 用户要求，按钮上写零钱余额），旁边"存进存款""从存款取出"两个次级按钮（孩子和家长都有）。记一笔的弹窗在 iPhone / iPad 上键盘弹出时停在键盘上方，不会被盖住。Mac 上表头还有"期初余额""月利率 N%"。
4. 待转账提醒：本周练习奖励、上月利息；Mac 上每项有"已转账"按钮，iPad 上显示"等转账"。
5. 流水：**按月分组**，每月表头显示"2026年11月 收入 x 支出 y"；**这个月展开，过完的月份默认收起**（表头多显示"N 笔"），
   点表头展开 / 收起。月内再按日期倒序分组（"11月24日 周二 · 今天"，右边当天支出合计）。每条记录左边是分类 / 类型的圆形图标，
   中间标题和分类 / 说明，右边金额（收入主色带“+”，支出带“−”，存取款写"零钱 → 存款"）；能改的记录点一下打开编辑（可删除）。
6. 本月支出构成：环形图 + 分类列表（图标、占比、金额）。
7. 和微信对账：输入微信里实际的零钱和零钱通，显示和账本相差多少（"对上了 / 微信多 N 元 / 微信少 N 元"）；
   家长在 Mac 上写原因后一键生成对账调整（差多少调多少，零钱、存款各一条）。孩子看到"想想有没有忘记记的，或者找妈妈对账"。

样式遵守 `docs/style.md`（§积分 / 记账），保持简洁；金额用 `tabular-nums` 加粗，清楚易读；
iPad 上按钮和输入框不小于 44px。

## 8. 数据

- 记账记录孩子和家长会在不同设备上同时写，不能存进 app_settings 的单个 jsonb（整包 LWW 会互相覆盖）。
  新表 `ledger_entries`，每条记录一行，带 `updated_at`、`deleted_at`，走现有 LWW 同步和软删除：
  本地 Dexie（`ledgerEntries` 表，版本 10）先写、页面只读本地，云端模式再 upsert；拉取时按 updatedAt 合并，
  本地有、云端没有的新记录补传。迁移脚本 `docs/supabase-migration-ledger.sql`（幂等，不改现有数据，含 RLS 与 realtime）。
- 字段映射只有一份（`lib/ledgerRows.ts`），日常写入、日常拉取、维护面板上传、维护面板下载都用它；往返对照测试 `lib/__tests__/ledgerRows.test.ts`。
- 余额由记录计算得出，不单独保存可修改的余额。
- 练习奖励的"待转账"金额取自每周结算快照（`points_ledger_v1.snapshots[周一].allowance`）。
- 月利率修改记录存 app_settings `ledger_settings_v1`：`{ rates: [{ from: "YYYY-MM", rate, updatedAt }] }`，两台设备按起始月份合并、同月取较新的。
