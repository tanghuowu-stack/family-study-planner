## 1. 功能定位

**习惯打卡：若干「打卡项目」各自一张月历，各自独立计连续。**

打卡页（原“统计与设置”，2026-11-13 拆分，设置项移到独立“设置”页）从上到下两块：打卡区（本卡范围）→ 课程节数统计。
打卡区是一张矩阵：行是打卡项目，列是本月每一天，行尾是本月完成天数；月份切换和图例只有一份（原先每个项目一张整宽月历卡）。
没有"总打卡"概念——每个项目自己的月历、自己的 🔥连续天数，互不影响。

## 2. 打卡项目的管理方式

- 入口只在统计页：「管理打卡项目」弹窗，勾选/取消即时生效。
  **任务表单里没有打卡设置**（曾有"计入打卡"勾选框，已移除）。
- 候选 = 活跃的**重复类任务**（`isOccurrenceSchedule`，即 timeType=recurring），
  剔除软删、整体 cancelled、readingPlan。列表用分类兜底显示名
  （`taskShortName`：空标题的兴趣班显示"游泳课"等，不显示"(无标题)"）。
- 数据字段：任务本体 `enableStreak: boolean`（云端列 `enable_streak`）。
- 弹窗列表（2026-11-13）：已勾选项目和非上课类候选在主列表；**未勾选的上课类**（`isCourseTask`）
  折叠在「上课类 N 项（一般不用打卡）」里。未勾选项目右侧的「不再提示」只是从列表隐藏，任务本身不受影响。
  命中打卡分组的任务显示「计入「钢琴」月历」，与月历卡片名对应。这两项来自 `HabitCandidate`
  的只读派生字段 `isCourse` / `calendarTitle`，不落库。

## 2.5 打卡项目与间断的任务（2026-11-14）

- **一个打卡项目可以由好几段任务组成**。间断的事（比如单词听写：做一个月、停三个月、再做一个月）每次重新建任务，以前会在打卡页多出一行新项目、旧的那行也留着。现在新任务可以**接上**以前的项目：任务上记 `habitKey`（= 项目 key，即项目里最早那个任务的 id；存 metadata jsonb，不加列），打卡矩阵里合成一行，历史连在一起，名字用最近那个任务的。
- 项目归属 `habitProjectKey(task)`：固定分组（钢琴，`HABIT_GROUPS`）> `habitKey` > 任务自身 id。
- **接上的入口**：管理弹窗里勾选一个任务加入打卡时，先问“要接上以前的打卡吗？”。`suggestHabitLinks` 列出以前打过卡的项目（正在打卡的和已停的），按 `habitLinkScore` 排序：同分类同学科 +3（同学科不同分类 +1），名字里相同的两字词各 +2（最多 3 个）；分数 ≥3 的第一个预先选好。名字常常不一样，所以只排序、预选，由家长确认，不自动合并。都不是就选“作为新项目”。
- 接错了：在“正在打卡”里展开这个项目，把接上来的任务“移出”（清掉 `habitKey`，变回它自己一个项目）。
- 整个项目取消打卡：项目里所有已勾选的任务一起取消，起点保留。改起点：项目里打过卡的任务一起改。
- **旧数据不迁移**：以前已经分成好几行的不自动合并（用户 2026-11-14 定：旧数据不管）。
- **管理弹窗分栏**：正在打卡（一个项目一行，显示分类·安排·已停与最后日期·累计天数）/ 可以加入打卡（带分类·安排·起止，方便认出是哪个任务）/ 上课类、已结束的任务、已隐藏（折叠）。
- **矩阵**：这个月一天都没排的项目（停着的）不占一行，矩阵下方列出“这个月停着的项目不显示：…”。

## 3. 起点规则（streakStartDate）

- 勾选当天（本地日）自动写入 `streakStartDate`（云端列 `streak_start_date`），
  默认不需要手填、任务表单不暴露。
- **起点前的日子一律 off**，不计漏卡（解决"老任务后来才勾打卡，历史全判漏卡"的欠账问题）。
- 取消勾选：`enableStreak=false`，**起点保留**（历史月历可回看）。
- 重新勾选：起点**更新为重勾当天**。
- **手动可调**（2026-07-18 补，2026-11-13 改交互）：「管理打卡项目」弹窗里，每个已勾选项目下方
  有一个「打卡起点」日期框，可手动改早或改晚；未勾选项目不显示。
  约束：**不允许晚于今天**（不允许"起点在未来"这种无意义状态）。日期改动先进草稿，
  **点「确定」才保存**并刷新月历（日期框每拨一下月/日都会触发 change，边改边存会存进中间值）。
  函数：`setHabitStartDate(taskId, date)`。

## 4. 月历口径（getHabitCalendars，三态判定）

对每个勾选项目，某天的状态：

| 状态 | 判定（按此顺序） |
|---|---|
| `off` | 未来日；或**非应做日**（起点前 / 排期未命中 / 该日 occurrence 被单独取消）；或**休息日且未完成**（免罚，不算漏卡） |
| `done` | 应做日且已完成——**休息日当天做完了同样算 done**（完成判定优先于休息日） |
| `missed` | 应做日、未完成、且非休息日（含今天——今天应做未完成显示 missed，但不断连续，见 §5） |

- **应做日** = `scheduleOccursOn` 排期命中 ∧ 日期 ≥ streakStartDate ∧ 当天未被单独取消。
- **完成判定**（沿用完成日归因，R1 权威源）：
  - occurrence 类：当天 `task_occurrence_statuses` 行 `status=done`；
  - 非 occurrence 类：本体 `status=done` 且 `completedAt` 按 `toLocalDateKey`
    归因的本地完成日 ≤ 当天（完成日及其后的排期日视为满足）。
  - 所有 timestamp → 日期转换必须走 `toLocalDateKey`，禁止 UTC 截断。
- UI：绿=done、红=missed（rose 系，见 style.md 功能色）、灰=off；未来日留空；今天整列浅绿；休息日表头标“休”；
  图例：完成 / 漏卡 / 休息或无排期 / 今天。
- 月份切换：矩阵顶部一个月份切换，所有项目同步；🔥连续与展示月份无关。

## 5. 🔥单项连续的计算规则

**停久了从头算**（2026-11-14 用户定）：往回走时，连着超过 `STREAK_BREAK_GAP_DAYS = 14` 天没有安排（非应做日），连续天数就停在这里，不再接上更早的。间断的任务重新开始时从 1 算起；每周一次的项目两次之间只隔 6 天，不受影响。休息日（有安排但免罚）不算“没有安排”。


从今天往回逐日走（回看上限 400 天，且不早于该项排期起点 / 打卡起点）：

- 应做日已完成 → +1，继续往前（**休息日完成同样 +1**）；
- 应做日未完成 → **断**，停止——但若该日是休息日则**免罚穿过**（不 +1 也不断）；
- 非应做日 → 穿过（不 +1 也不断）；
- **今天**应做但未完成 → 不算断（当天还没结束），从昨天起算。

## 6. 休息日机制

- 入口：统计页「休息日」弹窗，点某天标记/取消（可切月）。
- 存储：app_settings `stats_rest_days`（string[]，YYYY-MM-DD），云端同步，全家共享。
- 效果：**"免罚"而非"不计"**（2026-07-18 定稿）——休息日没做不算漏卡（off、连续穿过不中断）；
  但当天**实际完成了就正常判 done、计入连续**，完成判定优先于休息日。

## 7. 数据层函数清单

| 函数 | 职责 |
|---|---|
| `getHabitCandidates()` | 候选任务列表（含 enabled 标记、已勾选项目的 streakStartDate），供管理弹窗 |
| `setHabitEnabled(taskId, enabled)` | 勾选/取消，走 `getRepository().update` 同步云端 |
| `setHabitStartDate(taskId, date, today?)` | 手动修改已勾选项目的打卡起点，不允许晚于今天 |
| `getHabitCalendars(month, today?)` | 全部勾选项目该月逐日三态 + currentStreak |
| `getRestDays()` / `toggleRestDay(date)` | 休息日读取/切换 |

## 8. 已废弃、不再实现（不是漏做）

以下功能曾实现过，2026-07-18 重构中**整体废弃删除**。
废弃原因：多项目共用一个"总打卡"导致口径混乱（三态判定、每日覆盖、补卡规则层层叠加），
真实使用中家长和孩子只关心"每个习惯各自坚持了多久"，用不到这些：

- 总连续打卡（所有项目全清才算一天）及总打卡月历
- 复活卡（余额/发卡/3 天补卡/家长长按确认）
- 六档坚持徽章
- 每日打卡项手动覆盖（added/removed）
- 本周完成率、学科对比

app_settings 里的历史键 `stats_revive_cards` / `stats_daily_overrides` 不清理，代码不再读写。
如果未来要做"完成率/趋势"类统计，另起功能设计，不要复活上面这套。
