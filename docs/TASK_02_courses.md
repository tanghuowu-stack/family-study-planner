# TASK_02 · 课程库 + 学科分类可配置化

> **推荐模型：Opus**（涉及新建表、RLS、与 tasks 关联、新建任务表单改造，是结构性改动）
> **前置依赖：建议 TASK_01 之后做**（先有稳定同步基础，再加新表更安全）
> **先读**：`PROJECT_GUIDE.md`，再读本卡。

---

## 解决什么问题

现在课程（游泳课、FCE 精讲等）和部分分类是写死的。课程会变动：游泳课上一阵就停、轮滑课季节性、美术课可能新增、初中要加历史地理。每次改都动代码不合理。

**本质：把"课程/科目"从硬编码字符串变成用户可配置的数据。这是"加一张表"，不是重构现有 tasks。**

设计参考你已有的"假期设置"（plan_periods）——它就是一个独立的可配置模块，课程库用同样的模式。

---

## 关键设计决策（已和用户确认）

1. **学科分两类**：
   - **主学科**（语文/数学/英语，相对固定，未来初中加历史/地理）
   - **兴趣班/技能类**（游泳/轮滑/钢琴/美术，频繁变动）
   两类都做成可配置列表，但主学科变动少、兴趣班变动多，UI 上可区别对待。

2. **课程支持"固定上课规律 + 手动改"**：默认按规律（如游泳课每周二下午）自动生成任务，也允许手动调整单次。默认是规律生成。

3. **课程有状态**：进行中 / 已结课 / 计划中。结课的课程在新建任务时不再出现在选项里，但**历史任务和统计数据保留**（不删旧数据）。

4. **课程有起止日期**：到期自动失效，不用手动删。

---

## 要做的事

### 1. 新建 `courses` 表（Supabase）
建议字段（按需调整，但要覆盖以下语义）：
```
id            课程唯一 id
family_id     数据隔离（必须，配 RLS）
name          课程名称（如"游泳课""FCE精讲"）
category      所属一级分类（兴趣班 / 课外 等）
subject       所属学科（语文/数学/英语/其他，或兴趣班具体项）
kind          主学科 still 兴趣班（区分两套逻辑）
is_class      是否算"上课"（钢琴练习=false）
status        进行中 / 已结课 / 计划中
start_date    起
end_date      止（null=长期）
schedule      固定规律，jsonb（每周几、时间段等）
sort_order    排序
created_at / updated_at
```
- RLS：与其他表一致，用 `get_my_family_id()`，`authenticated` 给完整增删改查。
- 记得 date 字段只传 `YYYY-MM-DD` 或 null（铁律 2）。
- 加入 TASK_01 的 realtime publication（这样课程改动也能多端同步）。

### 2. tasks 关联课程
- 在 tasks 表加一个可选字段 `course_id`（关联 courses.id）。
- **向后兼容**：现有/手动任务可以没有 course_id（保持现在的自由输入方式）。course_id 是"可选增强"，不是强制。

### 3. 课程管理 UI
- 新增一个"课程管理"入口（参考"假期设置"的位置和形式，可放任务管理页或设置区）。
- 能增删改课程、设置规律、改状态（进行中/结课）。
- 结课的课程从新建任务的下拉里消失，但不影响历史数据。

### 4. 新建任务表单接入课程库
- 新建任务时，"课程"从课程库**选择**（下拉/按钮），而不是每次手打。
- 选了课程后，自动带出该课程的分类、是否上课、固定时间段等，减少手动填写。
- 仍保留"自由输入"作为兜底（不是所有任务都对应一门固定课程）。

---

## 数据迁移说明

用户数据量极小（55 条，且是暑假提前计划，可丢弃）。**不做复杂迁移**：本任务完成、测试通过后，用户会清空旧数据从零录入。所以本任务**不需要写迁移脚本把旧字符串课程转成 course_id**，只需保证新结构能正常新建/使用即可。

---

## 不要做

- 不要把现有 tasks 表大改（只加一个可选 course_id 字段）。
- 不要强制所有任务都必须关联课程。
- 不要在这个任务里做自动排课算法（按 schedule 生成任务的逻辑可以有，但不要做"智能"排课）。

---

## 验收标准

1. 能在 UI 里新增一门课（如"美术课"），设规律、起止、状态。
2. 新建任务时能从课程库选这门课，自动带出分类信息。
3. 把"游泳课"设为已结课，新建任务时它不再出现，但历史游泳课任务还在。
4. 课程改动能多端同步（依赖 TASK_01）。
5. 没有 course_id 的手动任务依然正常工作。
