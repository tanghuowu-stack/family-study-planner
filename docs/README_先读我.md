## 核心用法：为什么这样最省 Token

**不要把所有需求塞进一段长提示词。** 每次只让 Claude Code 读两个文件：
1. `PROJECT_GUIDE.md`（地基，每次都读）
2. 当前要做的那一张任务卡（只读这一张）

做实时同步时，它只读 GUIDE + TASK_01，完全不加载课程库、语音输入等无关内容。上下文最精简 = Token 最省。

每张任务卡底部都有"开场提示"，**直接复制粘贴给 Claude Code 即可**，不用你自己组织语言。

## 模型选择（你关心的省 Token）

每张卡顶部都标了推荐模型。原则：
- **Opus（聪明，贵）**：架构、新建数据流、容易出错返工的——TASK_01/02/07。一次做对，比反复返工省。
- **Sonnet（均衡）**：单页面逻辑、中等改动——TASK_03/04/06/08。
- **Haiku 或 Sonnet（便宜，快）**：纯样式、文案、小动画——TASK_05。

在 Claude Code 里可以切换模型。开一个新任务前，先按卡片顶部标注切到对应模型。

## 关键提醒（来自你的项目实际情况）

1. **⚠️ 数据不能再清空了**：这条提醒写于项目刚起步时（当时 55 条数据只是暑假提前占位）。**现在已经过时且危险**——系统里是家里几个月的真实打卡、作业完成记录，任何"清空重录""删表重建"式的改动都不允许，结构改动必须写迁移/兼容旧数据，删除一律走软删除（`deletedAt`），改前先确认影响范围。

2. **不是重构，是扩展**：你的底层架构（tasks 表的 jsonb 字段、软删除、RLS）已经很合理。课程库、多孩子都是"加一张表 + 加一个可选字段"，不动现有核心逻辑。心里有底，不用怕大改。

3. **三条铁律别破**（详见 GUIDE 第 4 节）：service_role key 不进前端、date 不传空字符串、删除用软删除。这几条是你踩过坑总结的，务必让 Claude Code 遵守。

4. **后端托管先不动**：国内访问慢的问题，根源是 Supabase 节点在新加坡，换 Vercel 或租阿里云跑前端都解决不了（瓶颈在数据库）。先把功能做完整、用一段时间感受真实延迟，确实影响体验了再单独评估"自托管 / 国内替代后端"，那是另一件大事，别和这次开发混在一起。

## 当前进展（2026-08-13 更新）

TASK_01~08 均已完成并多轮迭代过，项目早已不是"从零开始"的阶段。这份文件仍保留原始的任务卡说明作为**新任务的编写范式参考**，但开工前更该先看 `change-log.md` 了解现状，而不是照着"推荐执行顺序"从头做起。

**最近一批改动**（详见 `change-log.md` 对应日期条目）：
- 打卡统计改造为"按打卡项目分别显示月历"（TASK_08 最终形态），支持同类任务（如"钢琴课"+"钢琴练习"）按二级类型自动合并为同一张月历。

- "最近操作记录"（活动日志）现在合并显示所有设备（Mac / iPad / 手机）的操作，不再只显示本机；并支持对近 100 条记录一键撤回。
- "管理打卡项目"弹窗支持隐藏不需要的候选任务（隐藏项若被勾选为打卡项目会自动重新显示，避免"关不掉"）。
- 移除了"打印今日清单"功能（连同相关 CSS/组件代码）。
- 部署方式：**每次 `git push` 到 `main` 都会被 Vercel 自动构建上线**，生产地址 https://family-study-planner.vercel.app/ ，没有额外的手动部署步骤。
