# 学习生活规划系统：项目长期规则

本文是后续增量开发的长期约束。修改项目前应先阅读本文，并以当前任务的明确要求为准。

## 1. 分类规则

一级分类固定为：

- 学校作业
- 课外
- 兴趣班
- 事项

“课外”的二级类型为语文、数学、英语、其他；内容类型为上课、作业、练习、听写、背诵、其他。

“兴趣班”的二级类型为：

- 钢琴课
- 游泳课
- 轮滑课
- 钢琴练习

钢琴课、游泳课、轮滑课属于上课；钢琴练习属于家庭练习，不是上课。

“事项”的二级类型为休闲、旅游、考试或比赛、其他。内部 enum 可以继续使用 `temporary`；旧数据或旧备份中的“临时事项”必须兼容，用户界面统一显示为“事项”。

## 2. 月历显示规则

月历只显示真正需要按日期查看的计划类项目：

- 课外上课
- 钢琴课、游泳课、轮滑课
- 事项中的旅游、休闲、考试或比赛及其他计划

月历不显示：

- 学校作业
- 课外作业、练习、听写、背诵
- 钢琴练习
- 阅读计划
- 普通每日练习

已软删除任务、已取消 occurrence，以及明确设置为不在月历显示的任务，也不能出现在月历中。

## 3. 今日、周、月统计规则

- 日期范围作业在周计划和月计划汇总中按唯一任务统计一次。
- 课程按指定范围内实际发生的次数统计。
- 旅游统一按实际天数统计，不再按旅游标题重复统计一次。
- 考试或比赛按次数统计。
- 休闲沿用现有的按天或按次统计逻辑。
- 钢琴练习可以作为练习统计，但不属于上课。
- 已取消 occurrence 不进入对应日期及统计。

今日、周计划和月历以任务是否在目标日期实际发生为准，不得因为任务绑定的阶段与当前阶段不同而隐藏任务。

## 4. 阶段规则

- 页面只需要维护假期。
- 未绑定假期的任务默认属于平时。
- 任务管理支持“全部 / 当前阶段 / 平时 / 假期”筛选。
- 阶段用于任务管理筛选和提前录入假期安排。
- 今日、周计划和月历不得用阶段过滤掉实际发生的任务。

## 5. 删除、完成和日志规则

- 任务删除采用软删除，业务视图默认排除软删除记录。
- 已完成任务在任务管理中默认只显示最近 30 天，可手动展开更早记录；这只是展示限制，不删除历史数据。
- 操作日志必须保留。
- 日志记录本机名称、设备类型和浏览器信息。
- JSON 备份继续保留完整历史数据，并兼容旧分类、旧字段和旧名称。

## 6. 开发规则

- 必须在原项目上增量修改，不要重建项目。
- 没有明确要求时，不要修改其他稳定功能或做无关重构。
- 每次修改完成后运行 `npm run build`。
- 不要接入 Supabase，除非当前任务明确要求。
- 不要提交 `.env`、`.env.local` 或任何真实密钥。
- 不要在前端代码、日志、截图或文档中写入真实密钥。

## 7. Codex 设置建议

每次给用户生成 Codex 修改提示词时，都要附带“推荐 Codex 设置”。

推荐规则：

- 小范围样式、文案、按钮、显示修复：速度=快速，推理=中。
- 普通 bug 或单页面逻辑修复：速度=快速，推理=中。
- 涉及统计口径、IndexedDB 数据迁移、批量修改多个页面：速度=快速或默认，推理=高。
- 涉及 Supabase、登录、云同步、权限、RLS、数据库迁移：速度=默认，推理=高。

这些内容只是给用户的使用建议，不能替代用户在 Codex 界面里的实际设置。
