# TASK_07 · 语音输入 + AI 解析任务

> **推荐模型：Opus**（涉及前后端串联、API Key 安全、提示词设计，建模要对）
> **前置依赖：TASK_02 完成后**（AI 解析需要知道课程库/分类，才能正确归类）
> **先读**：`PROJECT_GUIDE.md`，再读本卡。

---

## 目标

在手机/iPad 上语音说一句自然语言（如"给我加几条任务：语文今天有篇作文，数学一张卷子，英语要听写"），系统自动解析成多条结构化任务并新建。

---

## 三步链路（关键认知）

1. **语音转文字 = 浏览器免费能力**：用 Web Speech API（Safari/Chrome 内置）。用户点麦克风→说话→浏览器转成文字。**零成本，不调任何 AI，不需要付费。**

2. **文字→结构化任务 = 调用便宜的 AI 模型**：把文字发给一个小模型，返回 JSON 数组（学科/标题/日期）。这步要花钱但极少。

3. **JSON→新建任务**：拿到 JSON 后走 App.tsx 现有的批量新建逻辑。

---

## 费用与账号（重要，写清楚免得误解）

- **和用户个人是不是 Claude/ChatGPT 会员无关**。会员额度是在官方 App 里聊天用的；网站调 API 是另一套"开发者按量计费"。
- 需要单独注册一个 AI 开发者账号（Anthropic 或 OpenAI 等），拿一个 **API Key**。
- 这个任务足够简单（一句话→固定 JSON），**用最便宜的小模型即可**（如 Haiku 档 / mini 档），一天用几次，月成本基本可忽略（几毛到几块人民币量级，按实际定价核算）。
- **API Key 绝不放前端**（同铁律 1 的精神）。Key 配在服务端：前端只把文字发给**你自己的后端接口**（Vercel Serverless Function / Edge Function），由后端拿 Key 去调 AI，再把 JSON 返回前端。前端永远看不到 Key。

---

## 要做的事

1. **前端麦克风按钮 + Web Speech API**：录音转文字，显示识别结果让用户确认（识别可能有错，给用户一个"确认/编辑"再提交的机会）。

2. **后端解析接口**（Vercel Function）：
   - 接收文字 + 当前日期 + 当前选中孩子（如有 TASK_06）。
   - 用服务端 API Key 调小模型。
   - **提示词要点**：告诉模型本项目的一级/二级分类、可选课程（来自课程库）、日期理解规则（今天/明天/本周几 → 具体 YYYY-MM-DD）、**必须只返回 JSON 数组、无任何多余文字、无 Markdown 代码块**。
   - 返回示例：
     ```json
     [
       {"category":"学校作业","subject":"语文","title":"作文","date":"2026-06-25"},
       {"category":"学校作业","subject":"数学","title":"卷子","date":"2026-06-25"}
     ]
     ```

3. **前端拿到 JSON → 预览 → 批量新建**：解析后先列出"将创建这几条任务"让用户确认，再批量走现有新建逻辑。**不要静默直接写库**，避免识别/解析出错乱建。

4. **错误兜底**：识别失败、解析返回非法 JSON、网络错误，都要给用户清晰提示，不要崩。

---

## 多端注意

- iPad/手机 Safari 对 Web Speech API 的支持要实测（不同 iOS 版本可能有差异），做好不支持时的降级（退回手动输入）。

---

## 不要做

- 不要把 API Key 放前端任何地方。
- 不要跳过"用户确认"直接批量写库。
- 不要追求一次识别一长段复杂指令，先把"几条简单任务"做稳。

---

## 验收标准

1. 点麦克风说话，能看到识别出的文字。
2. 说"语文今天作文、数学卷子、英语听写"，能解析成 3 条带正确学科和日期的任务。
3. 创建前有预览确认。
4. Key 不出现在任何前端代码/网络响应里（用浏览器开发者工具检查）。
5. 识别/解析失败有友好提示，能退回手动输入。
