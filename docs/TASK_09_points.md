# TASK_09 每周练习积分与零花钱

> 本文件是积分功能的唯一规则依据。凡是积分、零花钱兑现、庆祝效果、家长权限相关的改动，
> 先读本文件；实现与本文件不一致时，以本文件为准。需要偏离本文件时，先向用户说明并取得确认，
> 再同步修改本文件。
>
> 规则确定日期：2026-11-24（同日修订：积分奖励由"小红花 + 愿望"改为"零花钱"，零花钱怎么记账见 `docs/TASK_10_ledger.md`）

## 1. 目的

- 学校作业、本周作业是必须完成的，不用积分驱动。
- 积分只用来鼓励"每周练习"，尤其是经常完不成的钢琴、背诗、听写、FCE 听力、小白鸥。
- 作业做得快，就有时间多做练习、多挣分，以此间接鼓励作业做快。

## 2. 计分范围

| 内容 | 是否计分 |
|---|---|
| 右栏"每周练习" | 计分 |
| 左栏学校作业（家庭作业） | 不计分 |
| 左栏本周作业（页面上叫“本周课外作业”，后面琥珀色小胶囊“提前完成加3分”；大增语文、奥数班、FCE 作业等，有截止日） | 本身不计分；截止日之前做完（提前完成）**每项自动 +3**（见第 6 节） |
| 其他安排·其他（首页显示为"提醒"）、休闲、旅游 | 不计分 |

积分从 **2026-11-23（周一）这一周**开始计算，之前的周不补算。
一周为周一到周日。

## 3. 每周练习的计分设置

每项练习有两个设置：**每次分值**、**多做的部分是否计分**。

| 项目 | 参考本周目标 | 每次分值 | 多做的部分 |
|---|---|---|---|
| 钢琴练习 | 4 次 | 2 | 计分，每天最多算一次 |
| 我爱背诗 | 5 次 | 1 | 计分，每天最多算一次 |
| 英语单词听写 | 4 次 | 1 | 计分，每天最多算一次 |
| RAZ 阅读 | 10 本 | 1 | 平时**不计分**，只显示"本周多读了 N 本"；**本周练习全部达标后计分**（见 §4） |
| FCE 语用 | 12 篇 | 1 | 平时**不计分**，只显示"本周多做了 N 篇"；**本周练习全部达标后计分**（见 §4） |
| FCE 阅读 | 2 篇 | 2 | 计分 |
| FCE 听力 | 4 个 part | 1 | 计分（有空就做一个 part，不必一次做完） |
| 小白鸥（标题写“小白欧”也认） | 2 页 | **3（每页）**（2026-11-25 用户由 2 分改为 3 分） | 计分 |

- 本周目标以任务里的现有设置为准，上表只是参考。代码不得自动修改任何目标。
- 小白鸥改成每页 3 分时，现有的小白鸥任务已一次性改成 3 分（2026-11-25 已在两台设备上跑过，这段一次性代码随后删除）。新建的小白鸥任务按预设自动 3 分。
- 单位为"次"的项目（钢琴、背诗、听写）每天最多算一次。
- 以后新建的每周练习，默认每次分值 1、多做计分，可在 Mac 上的任务编辑对话框里修改。
- 设定原则：分值大约按"10 分钟左右算 1 分"；单次很短、一天就能刷完很多的项目，多做不计分，
  防止孩子刷容易的项目而不做钢琴、背诗、听写；等本周所有练习都达标了，再多做这些也计分（2026-11-25）。

## 4. 计分规则

| 情况 | 积分 |
|---|---|
| 每完成一次 | 得该项"每次分值" |
| 某项本周达到目标（不论哪天达标） | 再 **+2**（`REACH_BONUS`；2026-11-25 曾误改成 +3，同日按用户更正改回 +2） |
| 超过目标的部分 | 多做计分的项目继续按分值得分；多做不计分的项目（RAZ、FCE 语用）平时不得分、只显示提示，**本周所有练习都达标后，它们多做的部分也按分值得分** |
| 没达到目标 | 做了多少得多少，不扣分 |
| 家长奖励 | 由家长在 Mac 上手动加分或减分，必须写原因，可撤回 |

- **全部达标后多做也计分**（2026-11-25 用户新增）：本周参与计分的每一项练习都达到目标后，“多做不计分”的项目（RAZ、FCE 语用）超过目标的部分按每次分值计分——包括全部达标之前已经多做的部分（最后一项达标的那一下一起算进来）。之后如果撤销记录让某项又没达标，这部分分数也跟着没有。代码 `utils/points.ts` `unlockExtrasWhenAllReached`，结算快照、积分汇总、打勾加几分（`gainForLog`）都按这条算。
- 本周的得分和"多做"的判断只看本周内的完成记录，不结转到下周。
- 没有任何扣分规则，只有家长可以手动减分。

## 5. 零花钱：家长手动兑现（1 分 = 1 元，2026-11-26 起）

- **1 分 = 1 元**，积分从 2026-11-23 这一周开始算。
- **不再每周自动结算零花钱**：原来“每周日晚 8 点结算、快照里固定那周零花钱（`allowance`）、记账页自动出现‘待转账：练习奖励’、家长点‘已转账’入账”整套取消（2026-11-26 用户改）。
- **待兑现积分** = 从 2026-11-23 起已挣积分总和 − 所有没删的“练习奖励”记录金额。
  - 已挣积分 = 每周得分（练习分 + 提前完成 + 家长奖励和扣分）相加，**每周不托底**（扣成负数的周也照减）。
  - 不新增字段、不改数据库：积分仍由完成记录算出，待兑现也是算出来的（`utils/points.ts` `pendingRedeemPoints`）；“兑现”只是多一条练习奖励记录、从里面扣减，**不改达标奖励、“全部达标后多做计分”等任何计分**。
  - 兑现后再补勾 → 待兑现增加；撤销勾 → 待兑现减少，可以变成**负数 = 多兑了**，显示“多兑了 N 分，下次抵扣”，**不自动追回**（零钱不动，以后挣的分先抵掉）。
  - 删掉一条兑现记录（Mac 上在记账流水里删）→ 那部分积分回来，零钱也扣回。
- **怎么兑现**：只在 Mac 记账页，表头“兑现本周积分”按钮 → 弹窗显示“待兑现 N 分”，输入框默认填 N，**只能填 1 到 N 的整数**（N 取整数部分）；确认后生成一条“练习奖励”记录（id 随机，日期是当天，内容“兑现 N 分”），零钱 +N 元。待兑现 ≤ 0 时弹窗只显示提示、不能兑。代码 `data/ledgerService.ts` `redeemPoints`。按钮叫“兑现本周积分”，实际兑的是到现在为止所有没兑的积分（包括以前周没兑的）。
- 以前如果有固定 id 的旧练习奖励记录（`allowance-周一`），照样算作兑现记录扣减。
- **每周快照保留**：每周日晚 8 点起（或下次打开时补）给这一周拍快照，只固定那周每项的分值、目标、多做设置；之后再改分值或目标不影响那一周的得分。快照里旧的 `allowance` 字段留着不读，新快照不再写。
- 每周分开算分，不跨周累积目标。
- 原来的小红花（每满 60 分一朵）、愿望（写愿望、家长确认、兑换）已取消：界面、计算、庆祝都去掉，代码已删除。
  app_settings 里已有的愿望等旧数据留着不动（`points_ledger_v1` 里的 `wishes` 原样保留），代码不再读写。

## 6. 本周作业提前完成

- 本周作业（有截止日的作业）在截止日之前完成（不含截止日当天），即为提前完成。
- **学校作业不算**（2026-11-27 用户：周末家庭作业是周六到周日的时段作业，被排进了本周课外作业、做完还加分，不对）：学校作业不管是单日还是时段，都留在“学校家庭作业”里，和平常的单日家庭作业一样，不进本周课外作业、不加提前完成分（`isWeekPlanTask`、`isEarlyCompleted`、`getWeekPlanDone` 都排除 `school`）。
- 带小项的作业，所有小项都勾完才算完成。
- **提前完成每项自动 +3**（2026-11-25 用户改规则："提前完成加 3"，每次提前完成直接加 3；原来要家长在 Mac 上处理"待处理"、给 1 或 2 分）：
  - 算在做完的那一周（`utils/points.ts` `earlyItemsForWeek`、`EARLY_POINTS = 3`），进本周得分（也就进了待兑现），快照里记 `early`。
  - 按任务现在的状态算，不单独存：取消完成就不加了；检查发现没做好，家长把这项取消勾选（3 分自动去掉）或用家长奖励减分。
  - 改规则之前家长已经处理过（给过分或选了"不给"，`earlyDecisions` 里有记录）的作业不再自动加，免得重复。
  - 弹出中档庆祝"提前完成，加 3 分！"（下面一行"截止日之前做完的课外作业，每项自动加 3 分"）。
  - 不再有"待处理"：家长奖励对话框里只列"本周提前完成（每项自动 +3）"给家长看；每周练习最下面一行右边写"提前完成 +N"；积分明细多一行"提前完成（每项 +3）"。

## 7. 设备与权限

**家长操作只能在 Mac 上进行，iPad 上没有这些功能。** 不使用"长按 2 秒"来区分家长，
因为孩子同样可以长按。

| 操作 | iPad（孩子） | Mac（家长） |
|---|---|---|
| 当天任务和练习打勾、取消打勾 | 可以 | 可以 |
| 在过去日期补记（打勾或取消） | 没有此功能 | 可以 |
| 家长奖励：加分、减分、撤回（提前完成 +3 自动加，不用处理） | 只能看到合计，点击无反应 | 可以 |
| 记账：记支出、存进存款、从存款取出 | 可以（只能记今天的，只能改删当天自己记的） | 可以（任何日期，任何记录） |
| 记账：兑现积分、确认利息转账、期初余额、对账调整、改月利率 | 不显示 | 可以 |
| 修改练习的每次分值和多做设置 | 不显示 | 可以 |

- 设备判断：用是否支持触摸来区分（例如 `navigator.maxTouchPoints > 0` 视为触摸设备，不提供家长功能）。
  注意 iPadOS 的 Safari 默认会把自己标识为 Mac，不能只看 User-Agent。
- 手机同样视为触摸设备，不提供家长功能。

## 8. 打勾与补记

- 当天的打勾由孩子在 iPad 上操作。
- 过去日期的补记只能在 Mac 上操作；补记不触发庆祝效果。
- 补记记为所查看的那一天（沿用 asOfDate 逻辑）。
- 打勾被取消或撤回后，分数随之自动扣回（分数由完成记录计算得出）。

## 11. 数据原则

- 分数由完成记录计算得出，不保存可修改的总分，遵守 R1 权威源规则；**待兑现积分也不存**，每次用“已挣积分 − 没删的练习奖励记录”算出来。
- 需要单独保存的：每项练习的分值与多做设置、家长奖励记录、改规则之前提前完成作业的处理结果（`earlyDecisions`，只读保留）、
  已庆祝记录、每周快照（分值、目标、多做设置）。兑现记录就是记账的练习奖励记录，存 `ledger_entries` 表（TASK_10）。
- 优先存入 app_settings（复用现有 jsonb 读写和云端同步），不改数据库结构。
  如必须改 schema，先按 ARCHITECTURE_RULES §3.5 写 migration 交给用户执行，执行完再推送代码。
- 每周快照：每周日晚上 8 点起把该周的分值、目标、多做设置固定下来；那周没打开过应用的，下次打开时补拍。
  快照之后修改分值或目标，不影响那一周；补勾、撤回奖励照样改变那周得分和待兑现。旧快照里的 `allowance`（固定零花钱）不再读。
- 存在 Task 上的新字段按 ARCHITECTURE_RULES §3.1 补齐四个映射面并加对照测试。
